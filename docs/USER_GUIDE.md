# User guide

Manual privacy review is **off by default**. In Settings, enable Require manual privacy review before AI analysis when needed. Automatic regex/custom-term masking always remains enabled. Skipped review is not recorded as human approval. The review instructions below apply when you choose to review or enable the gate. Question drafting may use pending source-linked findings; attorney review remains required before final use.

1. Open the local URL and create a matter. Choose mask or block policy; enter custom sensitive terms before importing. Use synthetic documents for initial cloud tests.
2. Enter any folder path accessible to the local backend, or select a folder for browser upload. No configured folder allowlist is required. Selecting browser files does not upload them: click Upload selected folder. Import includes nested folders and processes files individually, with progress and Stop after current file. Retrying a folder skips within-matter duplicate content. Original bytes are preserved under opaque local IDs; SHA-256 enables duplicate detection. Duplicate occurrences are audited with relative names and references to the retained document; duplicate originals are not copied again.
3. Check the saved inventory, including failures and duplicates. The workflow panel distinguishes missing imports, import failures, pending privacy review and readiness for analysis. Unsupported files, encrypted documents, extraction errors, attachments and missing OCR must be resolved before complete-corpus analysis. To analyze a smaller supported subset, review failed files and explicitly acknowledge reduced scope before using Exclude failed files from analysis. Excluded records remain visible and the decision is audited; they have not been analyzed. Convert problematic sources to supported preservation copies in a fresh matter; preserve originals separately.
4. Open Privacy. Select a document, review its passages in pages of ten, and edit/approve individual passages as needed. After reviewing all passages, you may explicitly approve the entire reviewed document with one confirmation covering PII/PHI and retained names. This is a human review action, not automatic approval. Individual passage edits are screened again. Block mode checks for recognized sensitive values before document/bulk approval. Bulk approval leaves source text unchanged. No names are automatically removed unless configured as custom terms: decide whether to retain names under the applicable policy or replace them with stable tokens.

   For bulk approval, use Bulk document approval at the top of Privacy. Filter filenames, select individual documents or Select all matching pending documents, then click Bulk approve selected documents. The confirmation lists document/passage counts and requires one explicit acknowledgement covering all selected passages and retained names. Selection can span filters; the total selected count and confirmation list show the full scope. Bulk approval changes review metadata only, leaves text and completed analysis checkpoints unchanged, and does not approve generated findings or start AI analysis. Running analysis, stale snapshots, cross-workspace IDs, unreadable documents and excluded documents are rejected.
5. Select Gemini (default) or Ollama. Settings defaults to Full corpus analysis. On Witnesses, click Analyze full corpus to process every included passage in successive internal batches (default 25 passages). Select Manual batch in Settings to run one batch at a time. Privacy review alone does not produce witnesses. The analysis-status panel shows provider/model, progress, safe error messages and processed source filenames. Gemini errors never cause an automatic switch. Select Ollama explicitly if desired. Each run records provider/model, input hashes, revisions and manual-review status. Verified findings are committed after each passage passes quote and support checks. An interrupted/provider-failed batch retains completed verified passages; the next batch skips those same revisions for the same provider/model. A completed batch is not necessarily a completed corpus. Zero findings is distinct from a failed call; never fill an empty list with invented people.
6. Review witnesses, chronology and relationships. Select a witness profile to see involvement, that witness's chronology and connections together. Expand each source passage. A quote can be genuine while the generated statement misinterprets it. Approve only supported statements. Reject mistaken identities or unsupported connections. Profiles use cited narratives or concise evidence digests with explicit limitations; raw findings remain separately inspectable. Exact names are grouped; alias resolution and entity merging are future work.
7. In Witnesses, use the witness list or Show witness selector to inspect one or all witnesses. Each card includes Profile Summary, Relationships with Others, Chronology and Questions with citations. Click a citation such as `[D01 · page 2]` to open the source document name, permanent document ID, exact supporting quote and extracted passage. Approve/reject proposed findings there.
8. Click Prepare 50–200 questions for a witness with source-linked findings. Choose an outline template, alignment, proceeding, examination, question style, and a target count from 50 to 200 (default 100). Adverse alignment suggests leading questions; the attorney can override. Add topics; do not paste unreviewed confidential material into instructions. Generation runs in bounded batches of up to 20, removes exact normalized duplicates and rejects invalid claim IDs. If fewer valid questions are returned, the outline reports the actual count and shortfall rather than padding it. Live model quality and quota limits still require validation.
9. Review outlines in each witness's Questions section. Questions are paginated in groups of 25. Inspect citations, then use Edit / review to modify wording and save an approval/rejection. Original wording, source references, reviewer, time and audit metadata are retained. Edited premises still require human verification. Exploratory questions have no factual citations and must not assert unproven premises.
10. Export witness work product or an individual outline using the CSV buttons. CSV includes full source names, document IDs, locators, supporting excerpts and review status; display labels such as D01 are only local navigation labels. Audit also exports the complete workspace JSON. Exports contain sensitive matter information and must be protected. They do not include originals, API keys or raw provider replies. Word exports are available through Export Selected and Export All.

Privacy edits are frozen after findings exist so citations cannot silently drift. Create a new matter version to change evidence or privacy terms. Run history remains separate; repeated runs can produce duplicate proposed findings.

Settings displays provider defaults, model names and whether a Gemini key is configured. Save or replace the Gemini API key in Settings. The password field clears after saving; the key is stored in the local server .env, never returned to the browser, and takes effect immediately. Configure other credentials and model names in .env and restart.

Settings also provides a Gemini model selector, Load available models, Save model and Test Gemini connection. The connection test sends only a short synthetic example, never workspace documents. A model appearing in the catalog does not guarantee that generation is available to your account. The old default `gemini-2.5-flash` was rejected for this account; `gemini-3.8-flash` is the replacement default. Availability and quotas can change. HTTP 429/5xx failures receive at most three attempts with bounded backoff; authentication/model errors are shown immediately. Raw provider payloads and credentials are never included in user-facing errors.

## Delete and restore workspaces

Select a workspace and click Delete workspace beside the dropdown. The confirmation shows its document/passage/output counts and short ID; type the workspace name to move it to Trash. Manage workspaces supports selecting multiple entries and reviewing the same counts, followed by typing `DELETE N` for the selected count. No workspace is deleted merely by selecting it.

Deletion removes workspaces from the active dropdown and blocks ordinary access to their records. It is an audited, recoverable soft deletion: database records and local stored copies remain available for Restore in Trash. Original source folders are never changed. This is not permanent erasure and does not remove backups or exports. Running analysis blocks deletion. Bulk deletion reports partial completion if an entry cannot be deleted; already-deleted entries remain recoverable.

## Permanently purge Trash

In Trash, use Permanently delete beside a workspace, select several checkboxes and use Purge selected, or use Purge all Trash. These actions first show the selected names/IDs and counts for documents, passages, outputs, runs, audit history and stored files. Type the displayed `PURGE ...` confirmation before permanent deletion. Opening the preview or selecting checkboxes does not purge anything.

Permanent purge removes the selected workspace database records and managed stored copies. Restore is no longer available. Original input folders outside managed workspace storage, separate exports and backups are not removed. This is ordinary filesystem/database deletion, not forensic disk overwriting. A minimal operation receipt retains UUIDs, counts and timestamps, without source text or names.

Only trashed workspaces can be purged. The whole selection is validated before any changes, and running analyses or unsafe links block the operation. Files are staged inside managed storage before database deletion. If a file lock prevents final cleanup, Trash shows a pending operation rather than claiming completion. Resolve pending operation requires typing `RESOLVE PURGE`: it restores staged copies when the database transaction did not commit, or finishes deleting copies when database records were already purged. Pending operations must be resolved before restoring or retrying affected workspaces.

### Witness selection and local fallback models
The Witnesses selector includes discovered names; rejected-only records are labeled and remain accessible for correction. Selecting a witness shows approved and pending evidence counts. Expand **Review witness evidence and citations** to inspect sources and approve supported findings. Question drafting is available from pending source-linked findings. Review is required before final use. Privacy approval and attorney finding approval are separate steps. Similar names remain separate until reviewed; discovered names may include erroneous candidates that should be rejected.

In Settings, use **Load installed Ollama models**, choose an installed tag in **Ollama model**, and click **Save Ollama model**. This takes effect immediately; active runs retain their pinned model. Ollama remains the default provider. Choose Ollama explicitly for local analysis or question generation. Install the requested model using `ollama pull qwen3.5:9b` if absent. Model availability and a successful connectivity test do not establish legal analysis accuracy.

## Specialist witness work product
Click **Draft complete work product** on a witness card. The LangGraph workflow researches up to four retrieved passages, checks new findings, drafts cited profile paragraphs and possible factual/legal issues, assembles chronology, and drafts 50–200 questions using that witness's question settings. No external legal authorities are researched. Relationships are described in the narrative; detailed relationship findings appear under Relationships with Others in that witness's card.

The Witnesses checkbox **Automatically draft complete work product** is checked by default. In Full corpus mode, it drafts work product for each identified witness sequentially after source extraction finishes. Manual mode drafts after each batch. Uncheck it to run extraction alone. Each witness may require several minutes and multiple model calls. The button also works for witnesses already discovered before this feature was added. Questions settings, alignment and instructions apply to the draft; unknown alignment does not imply adverse status. Save stages and status are visible above the witness cards.

Drafting uses non-rejected source-linked findings, including findings awaiting review. Narrative, issues and questions remain drafts. Every narrative paragraph and issue cites underlying findings; citation buttons open document passages. A separate model pass checks support for narrative and question premises. This mitigates hallucinations but cannot guarantee correctness. Review identity, aliases, missing context, competing accounts, and each cited passage before final use. A possible legal issue is a hypothesis for attorney evaluation, not a statement of governing law or liability. Approving a profile does not approve its individual questions.

Manual privacy review is optional and off by default across extraction, profile/issue drafting, question generation and document-context editing. When off, Gemini processes extracted text and retained names without passage approvals or a workspace acknowledgement. Automatic regex/custom-term masking remains enabled. If you explicitly enable manual review in Settings, its approval gates apply again. Unreviewed passages remain labeled unreviewed rather than being auto-approved.

In Settings, **Index next 100 masked passages locally** creates embeddings with local Ollama `nomic-embed-text:latest`. Automatic mode (the default) continues until remaining work is complete; Manual mode indexes one batch per click. Known discovered names, regex identifiers and configured sensitive terms are masked before embedding. Newly discovered names or changed source revisions invalidate older embeddings; reindex to refresh. Unrecognized names may remain; all embeddings stay local. **Search documents** combines matter-scoped keyword matching with PostgreSQL vector similarity and shows cited source passages. Without a current index, keyword retrieval remains available and the coverage warning explains the limitation. Indexing is separate from witness extraction and never approves source text.


### Automatic indexing (default)
Settings → Local corpus search → **Indexing mode** offers **Automatic (default)** and **Manual**. The mode is saved locally and applies immediately. Automatic mode maintains the index for every active workspace, without keeping the browser open or repeatedly clicking a button. It checks saved fingerprints, processes bounded batches fairly across workspaces, and resumes unfinished work when the server restarts. New documents, source revisions and changed known-name masking are picked up on later scans. Workspaces in Trash are skipped.

The progress panel reports current/total passages, remaining work, indexing/queued/paused/error states and completion. Automatic indexing pauses for analysis in that workspace and for local Ollama analysis using the same resources. It retries embedding failures after a delay, retaining completed vectors. Switch to Manual to stop after the current passage; an in-flight embedding request may take time to return. The one-batch button becomes available once automatic work has stopped. Automatic indexing requires the backend and local Ollama to remain running; it does not run while the computer or server is off. It creates masked local embeddings only and never starts witness analysis, drafts, cloud processing or approvals.


### Clear, contextual examination questions
Question generation now includes a **document context tool** and an **attorney question editor**. The tool reads existing masked extracted passages and resolves referenced document IDs only within the current workspace. The editor is instructed to draft as an exceptionally skilled professional litigation attorney: short, precise questions, one issue at a time, appropriate to the selected examination style. This is an AI drafting role, not a representation that a licensed attorney has reviewed the output.

The first question(s) identify the exhibit/message using its ID plus useful verified date, sender, recipients or subject. Follow-ups can refer to “that email” or “that message,” retaining citations. The target is about 25 words per question; longer compound questions are split into sequences of up to three questions. Not every header field is repeated, and unavailable metadata is not invented. A message that merely mentions another document is not treated as the referenced document: the tool separately resolves its source. Ambiguous or missing references require manual review.

For an existing outline, click **Improve document context**. Only pending drafts are eligible. Approved and rejected questions remain unchanged. Original wording and citations are retained in each question's edit history and in the SQL audit trail. Open **Edit / review → Prior wording and edit history** to inspect earlier wording. A sequence can increase the question count; the local editor caps the resulting outline at 200 and retains originals if it cannot accept a supported rewrite. If a rewrite fails verification, its original draft is retained with a review note. No revision auto-approves a question.

Every accepted edit passes a separate source-support check, including message identity and metadata. Context citations point to actual extracted header/content passages. Missing or misleading metadata, ambiguous aliases, document authenticity and personal knowledge still require human review. When manual privacy review is off, Gemini can use additional document-context passages without privacy approval. Enabling manual review restores the approval gate. Local Ollama remains an explicitly selected alternative.


### UI color palettes
Settings → **Appearance** offers Workbench Classic plus eight palettes from Color-Hex's popular list: Beautiful Blues, Cappuccino, Shades of Teal, Faded Rose, Shades of Purple, Dusty Sage, Beach and Retro. Choose a dropdown option or click a swatch card for a live preview. **Save palette** persists the choice for this local application and future reloads/restarts; **Revert preview** restores the saved choice. Previewing alone does not overwrite it. Workbench Classic remains the default.

Each palette card shows its original five hex colors and a link to the source page. Text, buttons and surface shades are derived where needed for readability; warning, approved, rejected and dangerous-action colors retain their meanings. Palette data is bundled locally, so using the picker does not contact Color-Hex or transmit document data. Links open the original website only when clicked.


### Stable evidence review and bulk options
The **Review witness evidence and citations** list now retains its expansion, selections, table scroll and bulk scope while review actions refresh the current workspace/witness. Rejected findings remain available for correction, including witnesses whose findings are all rejected; their dropdown entries are labeled accordingly and cannot support question drafting until non-rejected evidence is available.

Use **Select all listed evidence**, or individual row checkboxes, then **Approve selected**, **Reject selected**, or **Mark selected needs review**. For larger approvals, choose **Bulk approval scope**: this witness's pending evidence, all pending workspace evidence, this witness's pending questions, all pending workspace questions, or all pending workspace evidence and questions. Click **Approve all pending in scope**. The preview identifies the workspace, scope and evidence/question counts; acknowledge that you reviewed the items and citations before confirming. The Witnesses page also has a **Bulk review** shortcut.

All-pending operations leave already approved/rejected items untouched. Explicit selected-row actions can change an earlier finding decision. Bulk operations change review metadata only, preserve wording, and write audit snapshots/counts. They do not approve source privacy, approve narrative profiles, invoke AI or send documents anywhere. Source-less/excluded evidence or questions with invalid/rejected citations must be resolved before bulk approval. If anything changed since preview, refresh and preview again; no partial batch is applied. No existing evidence is bulk-approved merely by opening the controls.


### Sparse witness profiles and chronology limits
The Witnesses page distinguishes a readable profile from extracted source findings. When no suitable current narrative exists, it shows a conservative, cited description using explicit supported role findings, rather than pasting first-person messages into “Profile summary.” Raw excerpts remain under **Inspect supporting findings and citations**. That inspector preserves its open state during review refreshes.

A limited-evidence notice explains when the current findings do not support a fuller profile. Repeated role statements and generic first-person review snippets do not count as additional substantive profile points. The counts are a display heuristic, not a confidence score or a finding that the full corpus contains no more evidence. Similarly named people remain separate; where names share a first name, the page calls out the separate records. Selecting Dana Vale must show Dana Vale; Dana Voss retains its own profile.

Chronology includes supported dated event findings only. If none are available, the page explicitly says a reliable dated chronology cannot yet be built. Undated findings remain in the evidence inspector; the app does not invent dates or automatically substitute message timestamps for event dates. The page reports extraction checkpoint coverage separately from indexing: an indexed corpus may still be only partly analyzed for witnesses. Continue analysis and inspect sources before treating a brief profile or empty chronology as a complete-corpus result.

Future narrative generation is instructed to use short third-person descriptions of the exact witness. Sparse profiles are limited to one or two sentences (at most 60 words), with no padded responsibilities or ungrounded speaker attribution. Unsuitable/stale narratives fall back to the current concise digest, with limitations shown. This does not change stored evidence, approvals, or identities.


### One workbench per witness
Chronology, Relationships and Questions no longer have separate top-level tabs. Open **Witnesses**, select a person, and review their **Profile Summary → Relationships with Others → Chronology → Questions** in one card. Supported issues may appear with the profile. Every relationship/event/question keeps its evidence citations and review controls. Empty or sparse sections retain their explicit limitations notices.

A selected witness's Questions section contains the template, alignment, proceeding, examination, style, target count, optional attorney instructions, evidence review/bulk controls and saved outlines. The form is explicitly labeled with that witness's name. **Prepare 50–200 questions** jumps to that section. With All witnesses selected, each card shows saved work and a Configure questions button that opens the chosen witness's editor. Rejected-only records stay accessible for correcting evidence, while generation remains disabled without active findings.

Unsaved question form values are held separately for each workspace/witness in browser memory during navigation and application refresh. A full browser reload resets those unsaved form drafts; generated outlines and their saved settings remain in SQL. Automatic complete-work-product drafting uses the target witness's current/default question settings. Bulk review, pagination, source inspection and question edit history stay within the witness workbench.


### Gemini processing without privacy approval
The active configuration allows Gemini to process the corpus without privacy approvals. Manual privacy review is off, and there are no additional mandatory name/context approvals hidden in profile or question workflows. Automatic masking still applies to extracted text and attorney instructions; block-mode detection does not stop generation while manual review is off. Source text is not silently unmasked or marked human-reviewed. Source/citation verification, extraction-error handling and attorney review of final work product remain separate. Selecting a provider/model or authorizing processing does not by itself start a new corpus-wide run.

## Full corpus controls

Full corpus is the default analysis scope in Settings. Changing scope affects future runs; it does not cancel an active run. Starting analysis still requires clicking Analyze full corpus. The server continues without an open browser and displays passage/document coverage and witness drafting progress. Pause takes effect at the next passage or witness boundary; Resume retains verified checkpoints. Cancel releases the workspace for source changes. Paused runs keep sources frozen. Provider/model are pinned for the run; checkpoints from another provider/model do not count. Failed documents must be resolved or explicitly excluded. Coverage measures included sources processed, not a guarantee that every fact or witness has been found.

Question generation now shows the latest run status and safe provider error directly under the relevant witness. Gemini HTTP 503 indicates a provider outage/overload after bounded retries, not a privacy rejection. Use Review settings and retry, or explicitly choose local Ollama in the provider menu. Provider selection is never silently switched. Existing saved outlines remain available after failed retries.

Question progress stays visible in Witnesses and polls the server every three seconds. The activity bar is indeterminate during model calls; a separate count shows verified questions toward the requested target, not an estimated completion time. Failures observed during a run open a dialog with safe exception code, HTTP status, run ID, provider/model and last stage. View error details reopens a saved failure. Raw tracebacks, credentials and provider payloads are not displayed.
